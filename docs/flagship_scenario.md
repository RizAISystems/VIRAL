# Flagship Scenario

The public demonstrator uses one continuous synthetic engineering story rather than disconnected feature examples.

## Phase 1 — conformant operation

Request, actuator effort, achieved state, correction channels and thermal response remain inside the expected synthetic relationship. No driver report is present and no action is justified.

## Phase 2 — early precursor

An early thermal-shaped non-conformance appears while the vehicle remains operational and all hard limits remain unbroken. The reasoner temporarily favors a thermal-management explanation.

## Phase 3 — control effort changes before performance output fails

The synthetic actuator effort required to maintain the requested air-charge state begins to rise.

At first, achieved output remains near target. This provides evidence of changing vehicle behavior **before the performance channel itself materially diverges**.

## Phase 4 — new evidence changes the explanation

The earlier coolant signal begins to recover while actuator effort continues to rise. Requested-versus-achieved air-charge error grows and intake/correction channels add support.

The reasoner revises its preferred explanation to an air-charge / performance-control deviation.

## Phase 5 — projected margin loss

The vehicle remains operational and no hard threshold has been crossed, but recent behavior projects a critically narrow synthetic engineering margin.

## Phase 6 — bounded preservation

The deterministic authority policy decides whether the synthetic preservation response is permitted.

At A3 the simulator may reduce demand inside the public demonstration envelope. At A1 the same reasoning occurs but action is blocked.

## Phase 7 — preservation verification

The system continues observing the vehicle after the action and verifies whether the operating relationship is recovering. An action is not assumed successful merely because it was issued.

## Phase 8 — condition-based maintenance

The event is then treated as engineering evidence across time. Repeated relationship drift becomes a maintenance recommendation for the affected system before the next comparable high-load session.

This is condition-based reasoning, not a mileage interval and not a fault-code trigger.

## Phase 9 — engineering improvement

The same evidence is converted into ranked engineering responses. The public demonstrator compares three synthetic paths:

1. flow-path efficiency redesign
2. charge-air heat-rejection upgrade
3. calibration-only preservation envelope

Each option includes an engineering objective and explicit tradeoffs.

## Phase 10 — design requirement

The system checks a small synthetic candidate set against thermal, pressure-drop, mass and packaging constraints.

No candidate meets every constraint, so V.I.R.A.L. generates a measurable design requirement for a purpose-designed solution rather than force-fitting an available part.

## Phase 11 — modification validation

A second synthetic run repeats the same duty cycle after an engineering revision.

The validator measures peak control effort, tracking error, minimum engineering margin and whether a stronger replacement bottleneck appears.

The change is accepted only if the original limitation improves under comparable conditions.

That closes the full public loop:

```text
awareness → diagnosis → prediction → preservation → maintenance
→ improvement decision → design requirement → modification → validation
```
